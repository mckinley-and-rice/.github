# 디자인

English: [DESIGN.md](./DESIGN.md)

이 값들의 정본은 우리 사이트가 실제로 출하하는 스타일시트 `redrob-labs/app/globals.css` 입니다.
아래 내용은 전부 그 파일에서 전사한 것이며, 기억으로 쓴 것이 아닙니다.

**전사하고, 기억으로 다시 타이핑하지 마십시오.** 기억으로 고른 근사값(정본이 `#2b52ff` 인데
`#2440ff`)은 한 표면에서는 거의 맞아 보이고 다른 표면과 나란히 놓이면 눈에 띄게 틀립니다. 토큰이
필요하면 정본 파일을 열어 값을 복사하십시오.

## 두 개의 채널

팔레트 두 벌이 아니라 채널 한 쌍에서 두 테마가 나옵니다.

- `--ink` 는 페이지 위에 쓰는 것입니다.
- `--paper` 는 페이지 자체입니다.

공백으로 구분된 RGB 성분으로 저장해, 둘이 뒤바뀌어도 틴트가 의미를 유지합니다.
`rgb(var(--ink) / 0.5)` 는 두 테마 모두에서 "절반 세기의 텍스트" 입니다. 터미널 카드처럼 두 테마
모두에서 어두운 것은 자기 리터럴 색을 그대로 갖고 이 채널을 쓰지 않습니다.

## 토큰

| 토큰 | 라이트 | 다크 |
|---|---|---|
| `--ink` | `10 10 10` | `237 237 235` |
| `--paper` | `255 255 255` | `13 13 15` |
| `--background` | `#ffffff` | `#0d0d0f` |
| `--foreground` | `#0a0a0a` | `#ededeb` |
| `--muted` | `#6b7280` | `#9b9ba4` |
| `--accent` | `#0a0a0a` | `#ededeb` |
| `--surface` | `#f9f8f6` | `#16161a` |
| `--surface-veil` | `rgb(249 248 246 / 0.92)` | `rgb(22 22 26 / 0.92)` |
| `--code-bg` | `#f4f4f5` | `#17171a` |
| `--pill-border` | `#d5d9e2` | `#33333c` |
| `--border` | `rgb(var(--ink) / 0.08)` | 같은 식 |
| `--shadow` | `15 23 42` | `0 0 0` |

**액센트는 무채색입니다.** 두 테마 모두에서 `--foreground` 입니다. 파랑은 로고 아트워크에만 있고
다른 어디에도 없습니다. 브랜드 색 버튼은 존재하지 않으며, 그것을 추가하는 일은 컴포넌트 결정이
아니라 브랜드 결정입니다.

**`--muted` 는 표면이 아니라 텍스트 색입니다.** 이것은 shadcn 관례와 반대입니다. shadcn에서는
`--muted` 가 표면이고 그 위의 텍스트가 `--muted-foreground` 입니다. shadcn 컴포넌트나 토큰 세트를
우리 트리에 가져오면 그것을 먼저 정리하십시오. `--muted` 를 표면으로 재정의하면 그것을 쓰는 모든
라벨이 흰 배경에 흰 글씨가 됩니다.

다크 모드는 `prefers-color-scheme` 과 명시적 `data-theme` 속성 둘 다에 반응하고, 명시적 속성이
이깁니다. 두 경로를 다 출하하십시오. 그래야 사용자의 수동 설정이 동작합니다.

## 타이포

```css
--font-sans: "Pretendard", "Apple SD Gothic Neo", "Noto Sans KR", sans-serif;
--font-mono: "IBM Plex Mono", "SFMono-Regular", Menlo, Consolas, monospace;
```

Pretendard는 가변 폰트(`PretendardVariable.woff2`, weight 축 `45 920`)로 `font-display: swap`
과 함께 출하됩니다. 한 패밀리로 라틴과 한글을 함께 덮으며, 그래서 별도의 한글 서체가 없습니다.

**폰트 파일은 vendoring하십시오. CDN에서 불러오지 마십시오.** CDN 폰트는 첫 페인트 뒤에 도착하고,
그것은 cold load마다 눈에 보이는 리플로우입니다.

한국어와 영어는 다르게 조판하며, 둘 다 필요합니다.

```css
:lang(ko) { letter-spacing: -0.015em; word-break: keep-all; overflow-wrap: break-word; }
:lang(en) { letter-spacing: -0.01em; }
html:lang(ko) { line-height: 1.75; }
html:lang(en) { line-height: 1.5; }
```

한국어가 낱말 중간에서 끊기는 것을 막는 것이 `word-break: keep-all` 입니다. 더 넉넉한 한국어 행간은
취향이 아닙니다. 한글은 그 공간이 필요합니다.

**행간은 루트에만 지정합니다.** 요소별로 지정했더니 제목의 자식이 본문 값을 물려받아, `<br>` 과
소프트 랩을 함께 지나며 줄바꿈된 제목이 한 블록 안에서 두 가지 행간을 갖게 됐습니다.

모노는 코드, 식별자, 버전, 개수, 금액에 씁니다. 어떤 숫자가 그 아래 숫자와 비교되도록 의도됐다면
그 숫자는 모노입니다.

## 라운딩

정본 스타일시트 전체에서 측정한 값: `9999px` 이 19개 규칙, `1rem` 이 9개, `0.75rem` 이 6개,
`16px` 이 5개.

- 필과 캡슐 모양: `9999px`.
- 카드와 패널: `0.75rem` 에서 `1rem`.
- 아바타: `50%`.

네 번째 카드 라운딩을 새로 만들지 말고 이 집합에서 고르십시오. 한 컴포넌트 안의 두 가지 라운딩은
둘 다 목록에 있는 값이어도 실수처럼 읽힙니다.

## 모션

인터랙션 지속 시간은 `0.15s` 이고, 정본 스타일시트에서 압도적으로 가장 많이 쓰인 값입니다. 등장과
더 큰 움직임은 `300ms` 에서 `700ms` 입니다. 배경 루프(마퀴, 펄스)는 초 단위로 돌며 시선을 끌어서는
안 됩니다.

등장하거나 자리를 잡는 모든 것의 이징:

```css
cubic-bezier(0.16, 1, 0.3, 1)
```

빠르게 시작해 천천히 정착하고, 그것이 장식이 아니라 반응이 빠른 것으로 읽힙니다.

**모든 애니메이션에 `prefers-reduced-motion` 분기가 필요합니다.** 정본 스타일시트에 다섯 개가
있습니다. 모션 축소는 상태 변화가 즉시 일어난다는 뜻이며, 그 요소가 아예 나타나지 않는다는 뜻이
아닙니다.

`transform` 과 `opacity` 를 애니메이션하십시오. 레이아웃 속성(`width`, `height`, `top`,
`margin`)을 애니메이션하면 브라우저가 매 프레임 레이아웃을 다시 계산합니다.

## 표면과 깊이

깊이는 드롭 섀도가 아니라 헤어라인 보더에서 나옵니다. `--border` 는 `--ink` 의 8% 틴트여서, 두 번째
토큰 없이 두 테마 모두에서 유지됩니다.

`--surface` 는 올라온 면, `--background` 는 페이지입니다. `--surface-veil` 은 같은 표면의 92%로,
스티키 헤더처럼 콘텐츠 위에 놓이면서 읽혀야 하는 것에 씁니다.

콘텐츠 뒤에 텍스처, 점 격자, 패턴을 깔지 마십시오. 22px 점 격자가 제품 표면에 한 번 출하되어 모든
카드와 라벨 밑에 텍스처를 깔았습니다. 배경 영역의 고유 색 개수를 측정해 제거했고, 그것이 텍스처와
평면 채움을 구별하는 방법입니다.

## 디자인 변경 검증

**빌드된 화면을 보십시오.** diff도, 소스도, 따로 떼어 놓은 컴포넌트도 아닙니다. CSS가 올바르게
읽히는 상태로, 초록불 빌드가 죽은 버튼, 아무도 원하지 않은 회색 채움, 보이지 않는 라벨, 아무 동작도
하지 않는 모드 토글을 출하했습니다.

레퍼런스가 있으면 눈대중하지 말고 픽셀을 측정하십시오. 좌표의 색, 바운딩 박스, 자간, 라운딩.
그런 다음 두 이미지를 나란히 붙여 비교하십시오. 요소별 측정은 크기만 검사하므로 누락된 배지,
동적 이름이 들어갈 자리의 고정 문자열, 안내 문구 없는 빈 섹션을 원리상 볼 수 없습니다.

시작하기 전에 밝혀 둘 한계 두 가지. macOS 레퍼런스와 리눅스 빌드는 글자 래스터 수준에서 일치할 수
없습니다(힌팅, 감마, 서브픽셀 렌더링이 다릅니다). 서체, 크기, 굵기, 기하만 맞추고 거기서
멈추십시오. 그리고 프로세스가 죽은 창의 스크린샷은 변경이 적용되지 않은 스크린샷과 똑같이 보입니다.
동일한 두 프레임에서 무엇을 결론 내리기 전에 프로세스가 살아 있고 창 제목이 예상한 것인지
확인하십시오.

## 작업 순서

토큰을 정의하고, 그것에 맞춰 UI를 만듭니다. 값을 인라인으로 고르고 나중에 문서화하는 것은 순서가
거꾸로이며, 즉시 갈라지는 두 번째 정본을 만듭니다.

토큰만 선언하고 화면의 겉모습을 바꾸지 않은 것도 끝난 작업이 아닙니다. 토큰은 쓰이기 위해
존재합니다.
